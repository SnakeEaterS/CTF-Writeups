### 2. exploiting the post request and gaining access to the admin page.

Now after doing our pre scans and checks we can start taking action with what I have found it lead me to using burp suite to modify the requests made. So what I did was send the POST to the repeater in burp suite.

Using the info gained from the nmap we know that Node.js is being used and the backend is most likely in javascript where we can parse .json files. We can do a NoSQL injection by first changing application/x-www-form-urlencoded to application/json this would still be a valid input as it can take in json structured like data. 

Next is by adding the payload into the body which is '{"$ne":"hi}' on username and password what this does is tell NoSQL that instead of looking for the password and username is 'hi' the database looks for accounts whose password and username is not equal to 'hi' giving us the first user on the database which satisfies this condition which could lead to a admin account as it is usually the one dev create first to debug and test. But unfortunately I only managed to get guest.

The next error I received is that 'required is not defined' I didn't know what this meant so I looked it up it seems that EJS does not automatically inherit standard node.js global functions which 'require' is so we need to is add 'process.mainModule.' to require so it can navigate to the mainModule.require and allow the environment to access the modules package folder allowing us to run the require function. In addition to this change I swapped the exec to execSync to force the server to block execution until the command completes.
